1What it's for

The command you'd otherwise look up.

Ask the way you'd ask a colleague. hi q knows your system, your folder, and your recent commands, and shows the command with its risk before you decide.

Remember a command

The flags for tar, find, or ffmpeg, for the versions installed on this machine.

$ hi q find files over 1 GB in my home folder

Ask about output

Pipe in a failing build or a log. The confirmation still comes from the terminal, so Enter runs the fix.

$ make test 2>&1 | hi q why does this fail $ journalctl -u docker -n 100 | hi q what is wrong

Chat in the folder

hi q on its own opens a prompt: ask, run what it proposes, and follow up. It remembers which commands ran and how they ended.

$ hi q q› how many md files are here?
2Try it

Your first question in a minute.

With Claude Code installed, hi q needs no key. Otherwise it asks for one model provider once.

  1. Install hi, if you haven't.

    $curl -fsSL https://hi5.sh/install.sh | sh

  2. Choose the model, and let it set up your shell, so questions need no quotes and q is a short name.

    $hi q --setup

  3. Ask for something. Enter runs it; Esc cancels.

    $hi q show the five largest folders here

  4. Have a command explained, without running anything.

    $hi q --explain 'tar -xzvf archive.tar.gz -C /tmp --strip-components=1'

  5. See exactly what it sends with each question.

    $hi q --context
3How it works

A little context, read-only looks, and a judgement hi makes itself.

The model proposes; hi decides how careful to be. Nothing runs until you press Enter.

{% include diagram.html name="q" %}

With each question goes a short description of where you are: your system and shell, the folder's first 50 names and its git state, which useful tools are installed, and your last 20 commands. Values that look like keys, tokens, or passwords are removed first. File contents are never sent.

The model can look before it proposes, with five read-only tools that hi runs itself: list a folder, read a file, read a command's help, check what's installed, and run a read-only command for 10 seconds at most. Anything else is refused, and the model has to propose it to you instead.

hi parses every command it shows, pipes and $(...) included, and sorts it as read-only, changes files, or dangerous. The model's own label can make that stricter, never looser.

4The details

Risk, models, privacy, and the shell.

What hi q checks, where your question goes, and how to use it from scripts.

How hi judges a command

ClassExamples
read-onlyls, du -sh *, git log, find without -delete
changes filesmv, mkdir, sed -i, git commit, a > redirect
dangeroussudo, dd, curl … | sh, git push --force, writes to /etc; Enter, then type yes

For mv, cp, rm, ln, chmod, and chown, every glob shows what it matches. A command hi can't parse counts as dangerous. These checks catch the usual mistakes; they don't make a command safe.

The model

hi q uses, in order: the model saved by hi q --setup, HI_Q_BASE_URL and HI_Q_MODEL, your team's hi server when it serves a model, an OpenAI, OpenRouter, or Anthropic key in the environment, and Claude Code.

Any OpenAI-compatible endpoint works: Ollama, vLLM, LM Studio, or a model you serve with hi compute serve. hi q --status shows which one is in use; --provider and --model change it for one question.

Shell integration

# hi q: fresh history, questions without quotes, and cd in this shell. command -v hi >/dev/null 2>&1 && eval "$(hi shell-init bash)"

hi q --setup offers these lines for ~/.bashrc or ~/.zshrc. They give hi q your current history and last exit status, questions that start with q without quoting, and cd, export, and source that change your own shell.

Scripts and pipes

$ hi q --print find large files over 1 GB in my home folder $ hi q --yes how much space is left on this disk

--print prints only the command. --yes runs read-only commands without asking; anything else still waits for Enter. Piped input keeps its start and end, up to 32 KB.

Project notes

- Check a change with `make check`; never run `make deploy`. - Logs are in `var/log/`, newest last.

A repository can tell hi q what the folder listing doesn't show, in .hi5/q.md. The repository writes it, so hi q asks once before using it, and again whenever it changes.

What stays on your machine

--no-context sends only your question. read never opens credential files such as .env, ~/.ssh, or .netrc.

Every command that runs is logged in ~/.local/state/hi/q/log.jsonl with its folder, prompt, class, and exit status, never its output. Commands run as you, with your environment, not in a sandbox.

Under the hood

The context. hi q sends your system, shell, and whether the core tools are GNU or BSD; the current folder, its first 50 names, and the git branch and state; installed tools such as rg, jq, or docker; the last 20 commands and, with shell integration, the last exit status; inside tmux, the last 100 lines of the pane; and anything piped in. hi q --context prints it.

The tools. list goes two levels deep at most. read returns up to 200 lines of a file in or below the current folder, and asks you first for files elsewhere. run takes only commands hi classes as read-only. A model that can't call tools is asked for its answer as JSON instead.

When a command fails, hi q offers to ask for a fix: the model gets the exit status and the end of the error output, and proposes something else, up to three times.

The conversation. hi q -c reopens the last one, kept in ~/.local/state/hi/q/last.json. The key from --setup is in ~/.config/hi/q-key, readable only by you.
