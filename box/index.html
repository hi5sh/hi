1What it's for

Code you don't fully trust, somewhere it can't reach.

A teammate's branch, a repository you just cloned, or an agent that works without asking: each runs in a box, sees the project, and nothing more.

Try someone else's code

Run a downloaded repository's tests without its Makefile reaching your keys.

$ git clone https://github.com/example/tool && cd tool $ hi box run -- make test

Reproduce a bug from clean

A fresh Ubuntu with git, Python, uv, Node.js, and Bun, and none of your dotfiles to hide the problem.

$ hi box shell box$ uv run pytest -x

Let an agent work unattended

hi agent starts Claude Code, Codex, Hermes, or Antigravity in a box, without permission prompts, on a branch of its own.

$ hi agent "make the flaky sync test reliable"
hi agent →
2Try it

Your first box in a minute.

On Ubuntu. The first box builds hi's image, which takes a few minutes once.

  1. Install hi, if you haven't.

    $curl -fsSL https://hi5.sh/install.sh | sh

  2. Install rootless Podman. Without it, hi uses Docker, whose daemon runs as root.

    $hi install podman

  3. Open a box in any project. Look for ~/.ssh; it isn't there.

    $cd ~/projects/myproject && hi box shell

  4. Run one command and get its exit status back.

    $hi box run -- make test

  5. Clean up. hi lists what it will remove and asks once.

    $hi box rm --all
3How it works

One box, one proxy, one way out.

The box sits on a private network with no route out and no name lookups. Its only way out is hi's proxy, which lets through the allowed hosts and logs every connection.

{% include diagram.html name="box" %}

The project is at the same path as on your machine, with its .git, so the box can commit. .git/hooks and .git/config are read-only: the box can't plant a hook that runs on your machine later.

Add --worktree and the box works on a new git worktree and the branch hi-box/<name>, so its changes stay out of your folder until you merge them. Agents always get one.

The box runs as you, with no extra privileges, a home folder of its own, at most 4,096 processes, and 16 GB of memory (--memory).

4The details

The network, the project's settings, and the GPU.

What to change when the defaults don't fit, and what a box does not protect you from.

Network presets

--networkAllows
lockedNothing
dev (default)GitHub, PyPI, npm, Go modules, crates.io, PyTorch, and Hugging Face
openEverything, still logged

Add one host with --allow <domain> when it starts, or with hi box allow <name> <domain> while it runs, with no restart.

Review what a box changed

$ hi box ls $ hi box diff myproject-2 Files M Makefile ⚠ runs on the host later

diff marks files that run on your machine later, such as a Makefile, package.json, .envrc, CI workflows, and editor tasks. Read those before you run anything from the branch, then git merge hi-box/<name>.

Per project: devcontainer.json

{ "image": "mcr.microsoft.com/devcontainers/python:3.12", "customizations": { "hi": { "network": "dev", "gpu": true, "domains": ["data.example.com"] } } }

hi box uses the file's image or Dockerfile, containerEnv, and postCreateCommand, and ignores, and says so, the fields that would run on your machine or widen the box, such as runArgs and mounts. It asks once before allowing domains, since the repository wrote them.

The GPU and your team's data

--gpu passes the Strix Halo's GPU into the box; ROCm's rocminfo finds it there. A box with the GPU shares the host's kernel and GPU driver, so it is a weaker boundary than one without.

--data lets hf and Python in the box download your team's Hugging Face datasets through the hi server. The box gets a placeholder token; the proxy adds the real one, which stays on the host.

What a box doesn't stop

The allowlist checks host names. It stops accidents and casual leaks, not determined code: that can still send the project to a host it is allowed to reach. Use --network locked when nothing should leave.

With Docker instead of rootless Podman, an escape from the box would be root on the machine. hi says so when it falls back.

Under the hood

hi keeps each box's state in ~/.local/state/hi/box/<name>/: its settings, its worktree, its home folder, its allowlist, and network.log.

It starts two containers: the box, hi-box-<name>, on a private network with no route out and no name lookups, and its proxy, hi-box-<name>-proxy, on both that network and a normal one. The proxy runs your hi binary read-only, allows connections only to the allowlist, and writes every decision to network.log.

The box runs as you, with --cap-drop=ALL and no-new-privileges, and gets HTTPS_PROXY pointing at the proxy and your git name and email for its commits.
