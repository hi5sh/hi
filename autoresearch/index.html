1What it's for

Turn agents' variation into progress.

Agents vary a lot from one attempt to the next: some are right, some wrong, and some look right without being right. hi checks every one and keeps the best.

Best of n

One task, a few tries, mixing agents, since different agents fail in different ways. You read the ranked table and keep one.

$ hi agent best-of 3 --agents claude,codex \ "make the loader 2x faster"

Rounds overnight

A number to improve: a loss, a benchmark, a Sharpe ratio. Each round starts from the best so far; hi commits a result only when it beats it.

$ hi agent best-of 4 --rounds 100 --edit train.py \ --score "make score" --lower program.md

Start from a template

A project already shaped for rounds, with a fixed, tested evaluation, frozen data, and a validation window and holdout outside the repository.

$ hi init autoresearch-ml charlm $ cd charlm && make data && make loop

2Try it

Best of two, then rounds.

In a git project with a check (make check) and, for rounds, a command that prints a number. hi shows the plan and asks before it starts: a run costs about n times the tokens of one, times the rounds.

  1. Install hi and rootless Podman, and sign in to Claude Code or Codex on this machine.

    $curl -fsSL https://hi5.sh/install.sh | sh && hi install podman

  2. Run one task twice, by two agents. hi runs make check in each box when its agent ends.

    $hi agent best-of 2 --agents claude,codex "make make check pass"

  3. Keep the one you want, by rank or by name. The others are removed with their branches.

    $hi agent best-of keep b-1 1

  4. Run rounds on a score. --edit is the only part of the project a result may change.

    $hi agent best-of 2 --rounds 5 --score "make score" --lower --edit src/ "<task>"

  5. Watch it, or close the terminal: the rounds go on. q leaves the view; s stops the run after this round.

    $hi agent best-of watch b-2
3How it works

The agents work. hi judges.

Rounds are Karpathy's autoresearch loop (try an idea, measure it, keep it only if it's better, repeat), with the judging moved from the agent to hi.

{% include diagram.html name="autoresearch" %}

hi judges, not the agent. When an agent ends, hi stops whatever it left running, snapshots its files, and runs your check and your score on them. An agent that says its tests pass, or that it improved the number, is checked, not believed.

Only hi commits. In rounds, agents work on scratch branches. hi adds one commit to the run's own branch, best-of/<run>/best, only when a result beats the best so far. Nothing is merged into your branch or pushed; git merge is your step.

Every round learns from the last. The next round's task tells the agents the best score and a table of every earlier attempt, with its score, result, and one-line idea, so they build on what worked and skip what didn't.

4The details

Scores, limits, and gains that hold.

Rounds keep whatever scores best, so the more they run, the more they fit the data the score reads. These are the parts that keep a long run honest.

The score and the baseline

--score "<command>" is any command that prints a number; hi takes the last number it prints. --lower or --higher says which way is better.

Before any agent starts, hi measures the baseline on your last commit, in a box with the run's options. A score that fails or prints no number stops the run there, before it costs tokens. --min-gain ignores gains smaller than the score's noise.

Limits are yours

OptionEnds the run
--rounds 50after 50 rounds (default 1; forever has no end)
--for 8hno round starts after 8 hours
--budget 30no round starts once agents have used $30 at API prices
--patience 10after 10 rounds without a gain

--max 30m limits each agent in each round. --then "make report" runs a command on your machine when the rounds end, for any reason.

Keep only gains that hold

$ hi agent best-of 3 --rounds 20 \ --score "make score" --higher --edit strategy.py \ --validate "make validate" \ --validate-data ../myproject-validation program.md

After each round, hi runs --validate on the winner in a container of its own, with no network, no .git, and only the --edit files from the box. The data is read-only at /box/data and never in an agent's box. A gain is kept only if its validation is no worse than the highest so far; --validate-slack allows for noise.

Keeping agents to the experiment

--edit train.py is the only part of the project a result may change. A result that changes anything else, such as the evaluation or its data, is disqualified, whatever its score.

The templates go further: their evaluation refuses code that reads files or imports modules outside a short list, so the editable file can't read the data it is scored on. Keep a holdout outside the repository and check the result on it once, at the end.

The ranked table

Column
CHECK✓ or ✗, and how long the check took
DIFFlines added and removed, and files changed
FLAGSchanged files that run on your machine later, such as a Makefile
SPENDdollars at API prices (Claude Code) or tokens (Codex)

The order is no judgement of quality: passing boxes that changed something come first, then fewer flagged files, then the smaller diff. Read the diff before you keep one.

One GPU, one score at a time

A score with a time budget, such as the best loss after five minutes of training, means nothing if boxes share the GPU. With --gpu, agents work at once, but hi scores the boxes one at a time, after every agent of the round is done.

Under the hood, one round

1. hi starts n boxes from the same commit (for rounds: the best so far), each on its own branch, best-of/<run>/<i>, with --agents taken in turn.

2. Each agent works on the task, unattended, without permission prompts.

3. When an agent ends, hi stops whatever it left running, snapshots its files, then runs --check and --score on that snapshot, under a time limit of twice the baseline's time plus a minute.

4. hi ranks the boxes. In best of n, you pick one with keep. In rounds, the best score is committed if it beats the best so far, and holds on validation if there is one, and every box is removed.

5. In rounds, the next round's task tells the agents the best score and what every earlier attempt tried and scored. hi keeps every attempt's files, kept or not, under refs/best-of/<run>/.

The rounds run in a process of their own, so they go on when you close the terminal or the SSH session; hi agent best-of resume goes on from the best so far, after a reboot too.
