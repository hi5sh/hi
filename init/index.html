1What it's for

A project an agent can check its own work in.

Agents do their best work when one command tells them whether a change is right. Every template has that command, make check, and tells the agents to run it.

A new library or script

uv, ruff, pyrefly, and pytest, with the package in src/.

$ hi init python pricing-tools

A small app with its own data

Bun alone: Bun.serve, React, SQLite, and one executable from bun run build. Or web, service, pipeline, and ml.

$ hi init app onboarding

A repository you already have

Add the agent settings, CI, and the managed blocks without moving or rewriting any of its code.

$ cd legacy-tool && hi init --adopt python --dry-run
2Try it

A project and a passing check in a minute.

The Python templates need uv, web needs Bun and Node.js, and app needs only Bun; hi install sets up all three.

  1. Install hi, if you haven't.

    $curl -fsSL https://hi5.sh/install.sh | sh

  2. Create a project. hi shows every file and command, and asks before it writes anything.

    $hi init python pricing-tools

  3. Run the check agents will run: the lockfile, formatting, lint, types, and tests.

    $cd pricing-tools && make check

  4. Hand it to an agent. It reads AGENTS.md and runs make check before it says it's done.

    $hi agent "add a total() function with a discount, with tests"

  5. Later, catch up with the templates. Add --dry-run to only see what would change.

    $hi init --update
3How it works

Layers in, a plan out, and a record of every file.

A template is a chain of layers: a base every project shares, then the stack. hi composes them, shows the plan, and writes only after you say yes.

{% include diagram.html name="init" %}

Every template gives you make check; AGENTS.md with a short block of rules, read by Claude Code through CLAUDE.md and by Codex directly; settings that keep Claude Code out of .env and secrets/; the hi skill, so agents know how to rent a GPU; and CI that runs make check on every push.

It never overwrites your work. In a folder that already has files, a file with other content stops hi before it writes anything. Running it again when everything matches does nothing.

It remembers what it wrote in .hi5/template.json: the template, the version of each layer, and a hash of every file. That's how --update knows what it may replace.

4The details

Templates, updates, CI, and your team's own.

What each template adds, and how a project keeps up as they improve.

The built-in templates

TemplateFor
pythonLibraries and scripts: uv, ruff, pyrefly, pytest
webWeb apps and dashboards: React, TypeScript, Vite, Bun, Biome
appSmall apps with their own data: Bun, React, SQLite
serviceAPIs: FastAPI, SQLAlchemy, Alembic, health endpoints
pipelineIngestion: one idempotent run --date, raw files landed first
mlTraining: PyTorch for CPU, CUDA, or ROCm, a two-step test
autoresearch-mlAgents improving training overnight with hi agent best-of

Each adds its own checks to make check: service that the health endpoints answer, pipeline that a rerun loads nothing new, ml that it trains for two steps.

Keeping up: three kinds of file

KindOn update
Owned: CLAUDE.md, CI, skillsReplaced, unless someone edited it
Managed: AGENTS.md, MakefileOnly the block between hi:begin and hi:end
Seeded: source, tests, README.mdNever touched

A file edited by hand is a conflict: hi leaves it alone and says so, or --force overwrites it. When the template changed a seeded file, hi writes the diff to docs/upgrades/<version>.md for an agent to apply.

Check it in CI

- run: curl -fsSL https://hi5.sh/install.sh | sh - run: ~/.local/bin/hi init --update --check

--check changes nothing and fails when the project is behind the templates or has conflicts. CI can't reach your team's hi server, so it checks the built-in layers and says which private ones it skipped.

Your team's templates

On a device connected to your team's hi server, hi init also offers the templates from your team's private repository, marked (private repo). hi checks they are signed by the server and keeps a copy, so they work when the server can't be reached.

The built-in templates are part of hi, so hi update is how you get their newest versions.

Options

--dry-runPrint the plan and stop
--yesDon't ask, for agents and scripts
--no-setupWrite the files, run no uv sync or bun install
--github <owner/repo>Also create a private GitHub repository and push
--name <name>The project's name; by default the folder's

Adopt an existing repository

hi init --adopt python adds the files hi owns and puts the managed blocks at the top of AGENTS.md, .gitignore, and Makefile, keeping what was there. It never adds starting files such as pyproject.toml; it lists the missing ones, so you know why make check may not pass yet.

Under the hood

.hi5/template.json records the template, the hi version or private commit of each layer, and a hash of every file it wrote with its kind and source. It holds no paths, user names, or secrets. Commit it: --update and --check depend on it.

Owned files the template no longer has are deleted on update, if nobody edited them. When an admin renames a private template source, --update finds the renamed one with the same layers and records its new name.

In ml, make picks the PyTorch build for the machine: rocm on a Strix Halo, cuda with an NVIDIA GPU, cpu otherwise. make help shows which, and TORCH = cpu in local.mk overrides it.

In a private template repository, each template is a folder with its layer.json in project_templates/, beside skills/, bundles/, and docs/.
