1What it's for

Rent the machine, use it like it's local, give it back.

hi hides each provider's own tool behind one set of commands, but it doesn't pretend they're the same: hardware names and prices stay the provider's own.

A script that runs to the end

A Python script with its dependencies in it runs on the GPU you name, streams its logs, and stops when it's done.

$ hi compute run --gpu a10g-small train.py

A machine for a while

A shell, a notebook, or a web app, with a port forwarded to your laptop, until you stop it or its time is up.

$ hi compute up --gpu G4 --max 2h $ hi compute ssh g4-3fa1

A model behind an API

llama.cpp on the GPU, with its OpenAI-compatible API tunnelled to localhost.

$ hi compute serve qwen3.8-flash-next
2Try it

A GPU in a few minutes.

With a Colab Pro+ or Hugging Face account. --dry-run on any start shows the exact request without sending it.

  1. Install hi, and the providers' command-line tools from its menu.

    $curl -fsSL https://hi5.sh/install.sh | sh

  2. Sign in and see which providers are ready.

    $hi login hf && hi compute providers

  3. Pick the hardware by the memory you need, with its price.

    $hi compute hardware

  4. Run a script for at most 30 minutes. hi says the price and asks first.

    $hi compute run --gpu t4-small --max 30m train.py

  5. Or let the menu ask. Every step prints the command it runs, so you learn the flags as you go.

    $hi compute
3How it works

Runs, instances, and a limit on both.

A run ends when its script does. An instance ends when you stop it, or when it reaches --max. They share ls, status, logs, stop, and the same limits.

{% include diagram.html name="compute" %}

Every machine stops by itself. Instances default to 4 hours and runs to 1 hour. Hugging Face stops the job itself; on Colab, a small process on your laptop stops it, and every hi compute ls also stops machines past their limit; on RunPod, a watchdog on the pod terminates it.

Paid hardware asks first, with the price, the limit, and on Hugging Face the account that pays. The default answer is no. In scripts, hi stops until you add --yes.

Hardware names are checked before hi calls the provider, because an unknown name can fall back to other hardware: the Colab CLI once turned an unknown GPU into an A100.

Shells, ports, and logs

$ hi compute ssh g4-3fa1 # a shell $ hi compute tunnel g4-3fa1 8888 # a port, here $ hi compute logs hf/6ab97cba6b030d633f69a5ea # setup and server logs $ hi compute stop --all

Refer to a machine by its name, or provider/name. --max none starts one with no limit, after a warning you must confirm.

A team's GPUs, through a hi server

Connected to a hi server (hi connect), the providers it manages go through it: the server holds the keys, an approver says yes in Slack, and budgets are per person and per group. A reason and a time limit are required.

$ hi compute up --on runpod --gpu rtx-4090 --max 2h --reason "LoRA sweep" $ hi compute requests # what's waiting $ hi compute extend rtx-4090-1c2d 1h

Your team's data in a run

--data ORG/NAME downloads your team's Hugging Face dataset into data/NAME before the script starts, through the hi server, so the machine never holds a token of yours.

--env KEY=VALUE sets a variable; --secret KEY passes $KEY as an encrypted secret on Hugging Face.

Under the hood

hi talks to Colab through the Colab CLI, and to Hugging Face Jobs, RunPod, and Shadeform through their REST APIs. --dry-run prints the exact command or request, as in the demo above.

A Python script goes to the machine as a base64 environment variable and runs with uv run, so the dependencies in its header install there. On Hugging Face the job runs in ghcr.io/astral-sh/uv:python3.12-bookworm, and --max becomes its timeoutSeconds.

For a managed provider, the start is a signed request to the hi server, with the device key in ~/.config/hi/device_key, your SSH public key, and the time limit. The server holds the provider key and starts the machine after an approval.
