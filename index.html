What it is

What is a software factory?

A software factory is an automated, repeatable production system that transforms engineering requests or ideas into verified, deployed software. hi5 is one for your company's internal apps.

Standardized workflows

Work moves through a predictable “paved road” from intake (tickets, bugs, or alerts) to planning, implementation, testing, and release.

AI and agentic automation

Modern software factories frequently use AI coding agents to handle routine implementation, write code, run isolated tests, and open pull requests.

Quality gates and sandboxes

Every task runs in an isolated environment (sandbox) with automated CI/CD checks, test validation, and code reviews.

Human governance

Humans define intent, set constraints, monitor telemetry and costs, and act as the final approval gate before code merges into production.

Why inside

Ideas will get built. The question is where.

People already build their own tools with AI. On a public vibe-coding platform, that tool lives outside everything IT runs. hi5 gives them the same zero-friction start, inside.

On a vibe-coding platform

  • Company data on someone else's servers.
  • A sign-in of its own, outside your SSO.
  • Whatever stack the platform picked.
  • IT finds out when it breaks.
  • No clean way to take it over.

In the hi5 software factory

  • On your machines, at internal addresses by default.
  • Your organisation's sign-in.
  • Your stack, from your developers' templates.
  • A Slack channel, tasks, and an owner from day one.
  • An ordinary git repository, ready for its custodians.
The whole lifecycle

One path, from idea to mission-critical.

One hi team carries an app the whole way, so nothing has to be rebuilt when it starts to matter.

  1. Ask

    Anyone says what they need in the team's Slack channel. The lead, an AI, asks what it needs to know and files a task when they agree.

  2. Start right

    The project starts from your template: your stack, toolchain, and rules, not whatever an agent guesses. Already have a prototype? hi team adopt brings it in.

  3. Build

    Vibe Devs build by chatting with Claude Code or Codex in the browser; Pro Devs get the terminal, VS Code, and SSH. The agents work in a box with no credentials.

  4. Try

    Each change lands on a preview at an internal address. People try it on their phone and send feedback from inside the app; it becomes the next task.

  5. Release and run

    Production changes only when a developer or an owner clicks Release, after a snapshot. Daily snapshots, watches, incidents, and a monthly budget keep it running.

  6. Hand over

    When a tool becomes critical, its custodians take it as it is: an ordinary repository from your template, with its history and tasks. Make IT the owners, or move it into your own pipeline.

Templates

Your developers set the rules. Everyone builds within them.

A template is the mould every project is pressed from. Your developers keep them in a private repository, and your hi server hands them to every machine. Prefer MongoDB, or Postgres? That's a line in how projects start.

  • The stackYour database of choice, your frameworks, your UI kit, and the way your apps connect to them.
  • The toolchainSetup commands, CI, and one make check every agent must pass before its work counts.
  • The rulesWhat agents are told in AGENTS.md, and the files and commands they may not touch.
  • Skills and rolesAgent skills and team roles that already know your systems.
  • Kept currenthi init --update brings a project up to the latest template, so apps don't drift apart.

Fits your organisation

Every role gets what it needs. Nothing more.

A hi team lives in one Slack channel and runs one app. People bring the ideas, developers build with coding agents, and IT, DevOps, and security keep the controls they already have.

colleagues

The people with the ideas

Ask in Slack, use the app, and send feedback from inside it. Contributors file bugs as tasks with their name on them. Nobody needs to read code.

Vibe Devs

Builders without code

Build by chatting with coding agents in the browser, on a task of their own, and release it with a click.

Pro Devs

Web developers

The terminal, VS Code, and SSH into the dev box, on the same tasks, branches, and previews as everyone else. They release too.

owners

IT

Set up the team and the infrastructure it runs on, and support the developers: who builds, which sites the dev box may reach, and a rollback when a release goes wrong.

platform

DevOps

Define the templates, toolchains, and checks. hi server holds the model keys, the budgets, and the private templates.

security

SecOps

Internal addresses by default and your organisation's sign-in. Agents in rootless boxes without credentials, every request out through a proxy, logged.

  • Ideas become tasks only when the person asking agrees.
  • Production changes only on the click of someone the owners chose.
  • Snapshots every day and before every release.
  • Keys never reach the agents, and the dev box reaches only allowed sites.

Install

install

CLI only most people

$curl -fsSL https://hi5.sh/install.sh | sh

Just the hi binary, checksum-verified, in ~/.local/bin. Update it later with hi update.

Workstation

$curl -fsSL https://hi5.sh/install.sh | sh -s -- install

Installs hi, then a menu to pick the workstation software for Ubuntu 26.04.

Strix Halo

$curl -fsSL https://hi5.sh/install.sh | sh -s -- install strix

The same menu with AMD ROCm for Strix Halo. Reboot once when it finishes.
