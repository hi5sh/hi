From idea to application

From idea to application. Together.

Someone in HR has an idea. With a hi team, she builds it with her colleagues and the team's agents, and keeps improving it.

  1. The idea

    Say what you need in Slack, in your own words. IT sets up a team for you with one command.

  2. The conversation

    The team's lead, an AI, asks what it needs to know and writes down what will change and how you'll check it. Nothing starts until you say yes.

  3. The build

    A coder agent builds it on a branch of its own. A reviewer agent, a different model, checks every change before you see it.

  4. The result

    A link that opens on your phone. Say what works and ask for more, from inside the app. It goes live when an owner says so.

hi team

Meet your new team.

A hi team lives in one Slack channel and builds one app for the people in it. You bring the ideas and the decisions; the agents bring the work.

people

You and your colleagues

Ask, agree, and try. You decide what gets built and when it goes live. Nobody needs to read code.

Hermes

The lead

Talks with you in plain language, plans the work, keeps the specs, and remembers what was said. It never writes code.

Claude Code

The coder

Builds each piece of work on a branch of its own, with tests, and learns the project's habits as it goes.

Codex

The reviewer

Checks the work against what you agreed to, and sends it back until it's right.

git

Developers, if you have them

The app is an ordinary git repository, on GitHub if you like, so people who read code can follow every change.

  • Nothing starts without a yes from one of the people.
  • Production changes only when an owner says so.
  • Snapshots every day and before every release.
  • Runs on your machine. Keys never reach the agents.

Agents

Different agents. Different strengths. One team.

The same tools a hi team uses, in your terminal. Hand work to Claude Code, Codex, or Hermes, try ideas several ways at once, and keep only what works.

hi agent

Delegate a task

Hand a task to any agent. It works without permission prompts in a box, on its own branch, and you get one report back, the same for every agent.

$ hi agent "make the flaky sync test reliable" The test now waits on the thread's event. Changed on hi-box/myproject-1: tests/test_sync.py
See hi agent in action →
hi agent best-of

Compare several attempts

Run one task several ways at once, mixing agents. hi runs your check on each result itself and ranks them; you keep the best.

$ hi agent best-of 3 --agents claude,codex \ "make the loader 2x faster"
Several attempts at once →
rounds

Improve overnight

Give a score to improve and let it run: each round starts from the best so far, and hi commits a result only when its score beats it.

$ hi agent best-of 4 --rounds 100 \ --score "make score" --lower

Building blocks

Explore the building blocks.

hi5 started as one command that turns fresh Ubuntu into an AI workstation. It's still the foundation: a single static binary, with no runtime to install.

install

CLI only most people

$curl -fsSL https://hi5.sh/install.sh | sh

Just the hi binary, checksum-verified, in ~/.local/bin. Update it later with hi update.

Workstation

$curl -fsSL https://hi5.sh/install.sh | sh -s -- install

Installs hi, then a menu to pick the workstation software for Ubuntu 26.04.

Strix Halo

$curl -fsSL https://hi5.sh/install.sh | sh -s -- install strix

The same menu with AMD ROCm for Strix Halo. Reboot once when it finishes.

Projects agents work well in

hi init starts a repository with one check agents run, short agent rules, safe settings, and CI, from built-in templates or your team's own. hi skills installs agent skills, pinned and audited. hi data downloads your team's private datasets without a token on your machine.

$ hi init python pricing-tools $ cd pricing-tools && make check

Every command
hi install [strix]

Install the workstation software; with strix, ROCm and GPU groups too, ending with a hardware report.

hi verify strix

Re-run the hardware report after the reboot. Nothing is uploaded.

hi net · status · down · reconnect

Join NetBird, then check, disconnect, or reconnect.

hi net expose <port>

A local service on a temporary public HTTPS address, password-protected by default.

hi init <template> <dir>

Start a project agents work well in; --update keeps it current.

hi q <what you want>

A shell command from plain words, or a chat.

hi agent <task>

A task for Claude Code, Codex, or Hermes, in a box, with one report.

hi agent best-of <n> <task>

One task in n boxes, checked and ranked; with --score, rounds that keep only gains.

hi team new <name>

A team of agents in one Slack channel that builds and runs an app.

hi box shell · run

A shell or a command in a rootless container with no credentials.

hi compute run · up · serve · stop

Remote GPUs on Colab, Hugging Face, RunPod, or Shadeform, with time limits.

hi connect <server>

Join your team's hi server.

hi data

Your team's private Hugging Face datasets, models, and buckets.

hi skills

Agent skills from skills.sh, pinned and audited.

hi adduser <name>

A user with render and video access.

hi update · version

Update hi, checksum-verified, or print its version.

Strix Halo

Tested on real silicon.

An AMD Ryzen AI Max+ 395 with Radeon 8060S graphics; the final report finds the GPU through amd-smi and rocminfo.

  1. Run the Strix Halo one-liner on Ubuntu 26.04.
  2. Pick a hostname and enter your sudo password.
  3. Reboot, then hi verify strix.
  4. hi net to join NetBird.
