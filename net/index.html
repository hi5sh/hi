1What it's for

A link for a colleague, a phone, or a webhook.

Most of what you build runs on localhost, where nobody else can see it. hi net expose gives it an HTTPS address for an hour, or as long as you say.

Show a colleague

A web app to try, behind a password hi makes up and prints. The login page asks for it.

$ hi net expose 3000

Open it on your phone

One link with the key in it: no login page and no password to type. Treat the link like a password.

$ hi net expose 5173 --link

Receive a webhook

Webhook senders can't pass a login page, so the address is open; your service checks the signature, as webhook receivers do.

$ hi net expose 8080 --public --max 30m
2Try it

Your first address in a minute.

On a machine in your NetBird network, with Peer Expose turned on once by a NetBird admin (Settings > Clients in the NetBird dashboard).

  1. Install hi, if you haven't. hi install installs NetBird.

    $curl -fsSL https://hi5.sh/install.sh | sh

  2. Join the network. Paste the setup key when asked; nothing is shown as you type, and it never lands in your shell history.

    $hi net

  3. Start something on a port, such as a folder of files.

    $python3 -m http.server 3000

  4. Expose it from another terminal. hi prints the address and the password.

    $hi net expose 3000

  5. End it with Ctrl+C, or let --max do it; the address stops working within seconds.

    $hi net expose stop --all
3How it works

NetBird's proxy in front, a small relay behind.

hi asks NetBird's reverse proxy for a public HTTPS address that leads through your NetBird network to the port, with a lock in front.

{% include diagram.html name="expose" %}

Services on localhost work. NetBird's proxy comes in over the VPN, at the machine's NetBird address, which most development servers don't listen on. hi runs a small relay there that passes requests on to localhost:<port>, keeping the Host header and WebSockets.

The lock is a login page for people in a browser: a password by default, a PIN, NetBird SSO for groups, or the key in the link. With --link, hi's relay keeps the key in a browser cookie until the address ends; scripts send it as an Authorization: Bearer header.

Every request is logged, in the terminal or, with --detach, in a file hi names, with the requests the lock turned away.

4The details

Locks, time, names that stay, and the network.

What to change when the defaults don't fit, and what to keep in mind.

Who gets in

OptionWho
(none)Whoever has the password hi made up
--password <text>Whoever has your password
--pin 482913Whoever has the 6-digit PIN
--linkWhoever has the whole link
--groups devopsNetBird users in those groups, through SSO
--publicAnyone with the address

How long, and in the background

$ hi net expose 3000 --max 30m # default 1h, at most 24h $ hi net expose 3000 --detach # prints the address, returns $ hi net expose ls # with passwords and end times $ hi net expose stop <name>

--json prints the address, the protection, and the end time for scripts and agents.

An address that stays

$ hi net expose 3000 --link --domain app.apps.example.com --max 720h

--domain puts the service on a name you choose, under a domain verified in NetBird (Reverse Proxy > Custom Domains), for up to 30 days. It needs a NetBird API token from a service user, in $NETBIRD_API_TOKEN.

A service that moves

--host points the relay at another address, such as a container's. --follow <file> relays to the port written in a file, read again whenever it changes, so a service can move to a new port without the address changing. hi teams put their apps on their addresses this way.

Joining the network

$ hi net # paste the setup key $ hi net --setup-key-file netbird-key.txt # from a script $ hi net status $ hi net reconnect

hi writes the key to a file only you can read, runs netbird up, and deletes the file whatever happens. hi net <setup-key> is refused, since it would put the key in your shell history.

What to keep in mind

Whatever the service lets people do, anyone past the lock can do; development servers often have debug pages and no sign-in. NetBird's proxy sees the traffic, since it handles the HTTPS, and other machines in the NetBird network can reach the service through the relay while it runs.

On a machine connected to a hi server, each exposure is in the server's audit log. NetBird's reverse proxy is in beta.
