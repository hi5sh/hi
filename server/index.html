1What it's for

GPUs for everyone, keys for nobody.

People join with hi connect and use the same hi compute commands as before. The server makes every provider call itself, and starts nothing until a person says yes.

Approve every start

Each paid start goes to a person who isn't the requester, in Slack or on the server box, with its reason, price, and time limit.

$ hi compute up --on runpod --gpu rtx-4090 --max 2h \ --reason "LoRA sweep for my thesis"

Know what it costs

Monthly budgets per user and group, a report in Slack every morning, and a live dashboard. Budgets warn; they never block.

$ hi server spend --since 7d

Share data and templates

The team's private Hugging Face data and project templates, to every connected device, with no token or GitHub access of their own.

$ hi data get example-org/prices-1d $ hi init analysis my-study
hi data →
2Try it

A server and its first user.

On a small always-on Linux machine in your NetBird network (see hi net), then on each person's machine.

  1. On the server box: create its state. It listens on the machine's NetBird address, port 7373, and prints a systemd unit to run it as a service.

    $hi server init

  2. Store a provider key. hi asks for it without echoing it.

    $hi server provider add runpod

  3. On a person's machine: join. hi makes a key for this device and waits for an admin.

    $hi connect hi.example.com

  4. On the server box: let them in, into a group.

    $hi server approve e-3f09a1 --group staff

  5. Check it from the person's machine.

    $hi connect status
3How it works

Signed requests in, provider calls out.

Devices sign every request with a key of their own. The server checks it, asks a person when the policy says so, and only then calls the provider with the team's key.

{% include diagram.html name="managed" %}

It listens only on its NetBird address. A forged, altered, or replayed request is refused, even from inside the VPN. Taking someone's access away is one command: hi server user remove.

The server stops every machine at its --max, even when the laptop that asked for it is off. Stopping never needs approval, and people can stop only their own machines.

Connections to a machine go straight to it, with the SSH key from the person's own ~/.ssh, not through the server. Colab is never managed: it always runs under your own Google sign-in.

4The details

Approvals, policy, budgets, data, and templates.

What an admin sets up, and what people see.

Approve and deny

$ hi server requests # what is waiting $ hi server approve r-9b41e0 $ hi server deny r-9b41e0 --reason "use a 4090, not an H100"

Admin commands talk to the running server through a socket only the server's user can open, so they work on the server box. With hi server slack setup, every request goes to a private Slack channel with buttons to approve, deny, and stop. Nobody can decide their own request.

Policy and budgets

SettingMeaning
max_hoursRefuse starts and extensions that would run longer
hardwareRefuse other hardware
auto_approveApprove without a person up to this price and total time
user_monthly_budget_usdWarn when a user in the group goes over
group_monthly_budget_usdWarn when the whole group goes over

hi server policy edit opens it in your editor and checks it. An over-budget request always waits for a person.

Your team's data

$ hi server data add example-org # asks for a read token $ hi server data test

One read-only Hugging Face token per organization stays on the server. Devices get a token for one repository that lasts a day, the server passes on only reads, and file contents come straight from Hugging Face's storage. See hi data.

Private project templates

$ hi server templates add private https://github.com/example-org/templates $ hi server templates list

hi init then offers the team's templates and agent skills next to the built-in ones. The server checks every new commit before devices get it, and devices check each bundle's signature.

Watch it

$ hi server ls # everything running, for every user $ hi server audit --since 7d $ hi server live --wall # read-only, for a shared screen

People see their own machines and budget with hi compute live.

Agents and the team's model

hi connect <server> --agent NAME --owner PERSON enrolls an agent that runs on its own, such as a build bot, with a person responsible for it. hi server ai set passes hi q's model requests to OpenRouter with the team's key.

Under the hood

The server keeps its state, audit log, and provider keys in ~/.local/state/hi/server, readable only by the user it runs as; --dir or HI_SERVER_DIR moves it.

hi connect creates a key for the device in ~/.config/hi/device_key, readable only by you, and signs every request with it. A request with no decision expires after 30 minutes.

If approved hardware is sold out by the time it starts, the server starts the cheapest free hardware with at least as much memory, at most twice the approved price or the approved price plus $1.00/h, whichever is higher, and says so.
