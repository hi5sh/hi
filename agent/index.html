1What it's for

Work that runs while you do something else.

The agent works unattended, so give it a task it can finish and check on its own. You read the report and the branch, and keep what's right.

A task you can check

"Make make check pass", "add tests for parse_config and fix what they find", or "upgrade FastAPI and fix what breaks".

$ hi agent codex --detach "upgrade FastAPI and fix what breaks" # … later $ hi agent wait myproject-2

A second opinion

Codex reviews what Claude Code wrote, from its branch, without changing a file.

$ hi agent codex --from hi-box/myproject-1 \ "review the last commit; don't edit files"

Work that isn't code

In a folder without git, the agent works in place. Bundles add skills and the tools they need, such as a browser or LibreOffice.

$ mkdir gpu-prices && cd gpu-prices $ hi agent --bundle web,office "compare the five largest Nordic GPU clouds in a Word document"
2Try it

Your first task in a few minutes.

On Ubuntu, with Claude Code, Codex, or Hermes installed and signed in on this machine. The first box builds hi's image, which takes a few minutes once.

  1. Install hi and rootless Podman, if you haven't.

    $curl -fsSL https://hi5.sh/install.sh | sh && hi install podman

  2. Hand it a task in a git project. Without a name, hi takes Claude Code, then Codex, then Hermes, whichever is signed in.

    $hi agent "make make check pass, and commit the fix"

  3. Follow it from another terminal if you like. In the first, Ctrl+C stops waiting, not the agent.

    $hi box attach myproject-1

  4. Read what it changed. Files that run on your machine later are marked.

    $hi box diff myproject-1

  5. Keep it, and remove the box. Its branch is kept.

    $git merge hi-box/myproject-1 && hi box rm myproject-1
3How it works

A box, a branch, and a proxy that holds the sign-in.

The agent starts from your last commit, on a new worktree and the branch hi-box/<name>, in a box with the project and nothing else from your home folder.

{% include diagram.html name="agent" %}

The agent never sees your token. Claude Code in the box holds the word hi-box-placeholder; hi's proxy outside the box swaps in your Claude sign-in on the way to Anthropic. Hermes' OpenRouter key stays outside the same way. Codex gets a copy of its sign-in for now, and hi copies a refreshed one back when the run ends.

The changed files come from git, not from the agent, so they are right even when the agent is wrong about what it did. hi asks every agent to end with a short summary, and the report has the same shape whichever agent did the work.

Uncommitted changes aren't in the box, since it starts from your last commit; hi says so when there are some. --from starts from another commit or branch instead.

4The details

Agents, models, briefs, bundles, and the report.

What to reach for when the one-line task isn't enough.

The agent and its model

$ hi agent claude "<task>" # Claude Code $ hi agent codex "<task>" # Codex $ hi agent hermes "<task>" # Hermes, on OpenRouter $ hi agent claude # interactive, in a box

--model picks the model, such as --model sonnet. Without it, the box uses the model in your own settings, so it behaves like the agent on this machine; Claude Code gets opus if your settings name none.

A long task as a brief

--- agent: claude bundles: [web, office] network: open --- # Nordic GPU providers Find the five largest GPU cloud providers in the Nordics…

hi agent briefs/gpu-prices.md reads the task from the file; - reads it from stdin. A brief can come from anyone, so what would widen the box (network, allow, data, gpu) is asked about first.

Bundles: skills and their tools

BundleGives the box
webagent-browser and its Chrome; needs an open network, which hi asks about
officeAnthropic's docx, xlsx, pptx, and pdf skills, LibreOffice, pandoc, and Tesseract
dataDuckDB's skills and CLI, pandas, matplotlib, seaborn, and plotly

The image is built once for each set of skills and reused. The skills go in the box's home folder, never in your project. hi bundle ls lists your team's bundles too.

The report, for scripts and other agents

$ hi agent codex --json "review the change on this branch; don't edit files" { "agent": "codex", "status": "done", "text": "The change looks right, but parse_date drops the time zone…", "report": {"status": "complete", "tests": "pass", "follow_ups": ["…"]}, "branch": "hi-box/myproject-3", "changed_files": [] }

With --json, the report is on stdout and everything else on stderr. It also has the tokens, steps, model, time, and Claude Code's cost at API prices. hi agent exits with 1 when the agent failed.

The box's options work here

--network, --allow, --gpu, --data, --here, --image, and --memory do what they do for hi box. --files <folder> gives the agent files to read, such as images or documents, read-only at /box/files.

For a project someone else wrote, --no-project-settings runs Claude Code without the project's own hooks, MCP servers, and permissions, and --max-budget-usd caps what it may spend.

When to hand it off

Hand a task to another agent for a second opinion from another vendor, a long or risky task that should run in a box while you carry on, or when one agent is out of quota.

Don't use it to split one task into pieces: the agents' own subagents do that better, because they share what they already know.

Under the hood, step by step

1. It checks the agent. Claude Code must be installed and signed in on this machine; hi says what is missing before it makes anything.

2. It makes a box, as hi box does: rootless Podman (or Docker, with a warning), devcontainer.json, the name myproject-1, and your last commit in a new worktree on hi-box/myproject-1.

3. It writes the allowlist from the network preset, the agent's own hosts, --allow, and the project's domains if you allowed them.

4. It starts the proxy, the box's only way out, on a private network with no route out. It is the only container that can read your Claude sign-in.

5. It starts the agent in the box. The agent sees the worktree, the repository's .git with hooks and config read-only, an empty home folder, and its own binary from your machine, read-only. ANTHROPIC_BASE_URL points at the proxy. The task goes to the agent on stdin, so a task of any length fits: claude -p --output-format json --dangerously-skip-permissions, or codex exec --dangerously-bypass-approvals-and-sandbox -o <file> -.

6. It waits for the box to stop, showing the agent's progress from its own session log, then stops the proxy.

7. It writes the report from the agent's result file, the box's exit status, and git diff against the commit it started from.
